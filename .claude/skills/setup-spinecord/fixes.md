# Fixes

Find the row whose problem matches the failing line, and do its fix. Then run the check of the state again.
If the same step fails 2 times, stop. Show the person the error line and this row, in their language.

| Problem | Cause | Fix |
|---|---|---|
| `bun`, `ant` or `claude` not found right after its install | This session has the old `PATH` | Use the `PATH` line of install.md for this OS in the same command |
| A tool not found in a new terminal of the person | The shell profile has no `PATH` line | Do the "every new terminal" step of install.md. On Windows, run the installer again |
| `git pull --ff-only` refuses | The clone has local changes | Stop. Show the error. Do not discard the changes |
| The login did not finish | The person closed the page, or 5 minutes passed | Run `bun scripts/setup.ts login` again. The browser opens again |
| The login browser does not open | No browser on this computer, or the agent runs on another computer | The person runs `ant auth login --profile credits --no-browser` in a terminal of their own, opens the URL, and pastes the code there. Then run `bun scripts/setup.ts login` |
| The login page cannot reach the computer, and `127.0.0.1` refuses | The agent runs in a command sandbox with its own network | Run the login command outside the sandbox, or let the person run it as in the row above |
| `Credit balance is too low` | The profile logged in to an organization with no credits | Run `bun scripts/setup.ts login --profile credits2`. The person picks the organization with the credits |
| Wrong Console organization | A profile keeps its first organization | Same fix as `Credit balance is too low` |
| Another credential pays | A new terminal of the person sets a variable that pays ahead of the profile. The line `pays` of `setup status` names it | Say the name of the variable, never its value. The person removes it from the shell profile that sets it. On macOS it can also be in `launchctl`: `launchctl unsetenv NAME`. On Linux, in `/etc/environment` or a file of an `environment.d` folder. On Windows, it is in the User or the Machine environment. User: `[Environment]::SetEnvironmentVariable('NAME', $null, 'User')`. Machine: the same with `'Machine'`, in a PowerShell opened as administrator. Then run the step again |
| Login method with the profile set | In the environment of a new terminal, the profile does not exist or has no login. So Claude Code takes its other login with no error | Run `bun scripts/setup.ts login`. Then run the step again. The line `host` is not the cause: the checks leave out the variables that it names |
| The environment of a new terminal could not be read | `setup` starts the login shell of the person, or on Windows reads the User and Machine environment with PowerShell. That failed or took more than 20 seconds. The line says why | Show the person the reason. If the line names a command, the person runs it in a new terminal, to see what the shell profile prints. A profile line that fails, waits for input or starts another program blocks it: the person fixes that line. No temporary folder, or a `'` in its path: the line names the folder. The agent sets `TMPDIR` to a writable folder with no `'` in its path, in the same command. No login shell: the person sets one with `chsh -s /bin/zsh` (macOS) or `chsh -s /bin/bash` (Linux). Then run the step again. Never remove this check |
| The login shell is csh or tcsh | These shells cannot run a command as a login shell, so `setup` cannot read their environment | Tell the person why. With the approval of the person, change the login shell: `chsh -s /bin/zsh` (macOS) or `chsh -s /bin/bash` (Linux). The person opens a new terminal. Then run the step again |
| No `Profile:` line on Windows | Claude Code does not find the profile that `ant` wrote | Run `ant --profile credits auth status`. Set `$env:ANTHROPIC_CONFIG_DIR` to its `Config dir:` path in the launch line and in this session. Run the step again |
| A doctor line `fail` | The line says why | The line `claude code`: run `bun scripts/setup.ts workshop`, which registers with local scope. Another line: run the command after `->`. If it names `bun apps/local/main.ts`, run it in `~/mi-robot` with the full path of the clone. Never use `-s user` |
| Port 8767 or 8769 held | Another Claude Code session runs spinecord | If that session is the robot's, use it: do not start a second one. Else the person closes the other Claude Code (type `/exit`, or archive the session in the app). Run the step again |
| `setup view` says nothing answers | The robot's Claude Code did not start, or it waits at a question. The line names a part of the workshop folder that is not ready | A part not ready: run `bun scripts/setup.ts workshop`. Credits: read the terminal with `read_terminal`, or ask what the window shows. A trust question: the down arrow to Yes, then Enter. App login: see the next row. Then run `bun scripts/setup.ts view` again |
| `setup smoke` says `Not logged in` on the app path | This agent does not run in the Claude desktop app, and `claude` has no login of its own | Run `claude auth status --text`. With no login, the person runs `claude auth login` in a new terminal and signs in with their plan. Or run `bun scripts/setup.ts choose credits` |
| No spinecord tools after the move | The session did not move, or the person did not allow the folder. The new folder loads its servers only at the next message | Ask the person to send one more message. Still none: run `claude mcp get spinecord` in `~/mi-robot`. If it shows no local scope, run `bun scripts/setup.ts workshop`. Then the person starts a new session in `~/mi-robot`, as see-it.md says |
| `setup window` could not open a window | This computer has no terminal app that the step can start, or the system refused | The person opens a new terminal, pastes the launch line of the `window` line and presses Enter |
| The 3D page says it has no connection between orders | The robot's server stops between orders: something drives it with short `claude -p` sessions | Drive only from the robot's Claude Code, which stays open. Reload the page while it runs |
| The person's Claude Code asks for a login method | The launch line did not set the profile, or it was typed in another folder | The person types `/exit`, then pastes the launch line again |
| The 3D page is blank or gray | The browser has no WebGL, or the page opened before the server | Reload the page. Else open it in Chrome or Edge |
| EV3 not `online` | The USB cable, the EV3 is off, or the browser is not Chrome or Edge | Connect the cable. Turn on the EV3. Open `http://127.0.0.1:8767/` in Chrome or Edge, and click Connect EV3 again |
| macOS firewall with `--lan` | The firewall blocks connections to bun | Run the fix of the doctor line `firewall`. It uses `sudo`: say why first |
