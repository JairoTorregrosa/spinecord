# deployments/example

A deployment is data only: robot files, and worlds of its own when it has them. Copy this folder, fill it in, give its files to the server (`bun apps/local/main.ts --help`). Packages never import from `deployments/`.

| File | What |
|---|---|
| `robots/r1.json` | The robot `r1`: LEGO EV3 educator base (motor pair B+C, wheel 5.6 cm, axle 12 cm, `forward_sign` 1). `pair` (the ports of the synced motor pair `ev3.pair`) and `hardware` configure the EV3 provider (`hardware.speech_volume_pct`, 1..100, is the loudness of `speak` on ev3dev and is required there), `profile` is the contract's RobotProfile. `profile.drivetrain` holds the wheel geometry, `max_drive_cm` and `max_turn_deg` (the longest drive and the largest turn of one call) and `heading`, the channel that measures the heading of a move: here the gyro's `angle_deg`, named by its role `gyro`; a base without `heading` measures it from the wheel encoders. `profile.drivetrain.forward_sign` is `1` when positive motor degrees drive the robot forward and `-1` when they drive it backward: check it on the real robot with a 5 cm `drive`. The same file serves the hardware robot (`--ev3`, `--ev3dev`) and its twin `r1-sim` (`--twin`); without arguments the server runs that twin, and each of those flags without a file uses this file. One shape and one validator: `parseRobotFile` in `packages/driver-ev3/robot-file.ts`. |
| `robots/arm.json` | The robot `arm`: a medium motor on A (role `gripper`), a large motor on B (role `lift`), a touch sensor on port 1 (role `limit`). No `pair` and no `profile.drivetrain`: there is no `ev3.pair` device, `describe_robot` shows `drivetrain: null`, `drive`, `turn` and `arc` answer `unsupported`, and `command_device` moves each motor. Its twin: `--twin deployments/example/robots/arm.json`. A twin's devices are what its world plugs in, so in the default room `arm-sim` shows three motors (A, B, C) and four sensors (touch on 1, gyro on 2, colour on 3, ultrasonic on 4): the motor on C and the sensors on 2, 3 and 4 are devices without a role. |
| `robots/pages.json` | The robot `pages`: no body. Its file is `{profile}` alone (no `hardware`, `pair` or `drivetrain`), it is online from the start with zero devices, and every device it has is lent by a browser page that joins it. `--pages` without a file uses this file; any `--pages` makes every robot of the process take pages. |

Worlds for a twin ship with the packages: `apps/local/examples/room.json`, `packages/sim-world/examples/`.
